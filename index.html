Kaggle Playground Series

S6E7 · S6E8

Tabular ensembles under a pre-registered improvement gate

Two Playground Series competitions run as a single research programme: a frozen cross-validation split, one metric, and a shipping threshold fixed before any result was seen. Every prediction artifact is keyed to that split, so out-of-fold matrices from runs weeks apart stay directly blendable.

  • S6E7 — 3-class health condition, scored on balanced accuracy against a heavily imbalanced training set. The shipped champion blends a bagged FT-Transformer with PLR numeric embeddings against a target-encoded XGBoost at a fixed 2:1 ratio. Finished rank 120 at private LB 0.95050, up 298 places in the shakeup.
  • S6E8 — binary classification over 691,369 rows × 12 features, scored on ROC AUC. Final submission is a four-family equal-weight blend of LightGBM, XGBoost, CatBoost, and a PyTorch MLP, at LB 0.96865.
  • Feature selection by SHAP consensus — TreeExplainer values from XGBoost, CatBoost, and LightGBM folded back onto source features, keeping the smallest set that reaches 95% of cumulative importance.
  • Optuna hyperparameter search on stratified subsamples with 3-fold CV, optimizing the competition metric directly. The largest single-leg gain it produced (+0.000544 solo) moved the blend +0.000068 and was not shipped.
  • Leakage discipline as the load-bearing constraint: target encoders, quantile bin edges, scalers, and category vocabularies are re-fit at every usage site — selection, tuning, and the final stack each get their own fit.
  • The shipping gate of +0.0002 AUC was derived from a seed twin and validated against 11 paired OOF/leaderboard runs (Spearman +0.973, residual σ 0.000131). It rejected five later probes, including the strongest solo model built.

Stack XGBoost · CatBoost · LightGBM · FT-Transformer · PyTorch · Optuna · SHAP · scikit-learn

Garden Planner

In progress

Agentic garden assistant with RAG and an agronomic watering model

A full-stack planning tool for vegetable and herb gardens: a React SPA and a FastAPI backend that plans beds, tracks plantings, and answers questions against your actual garden data. Started local-first on SQLite and now deployed for web and Android sync.

  • AI assistant runs a server-side agentic loop with 12 tools that read and write real garden state — companion planting, planting-calendar math from your frost dates, spacing capacity, task creation, weather, and watering. Tools execute in Python against the request’s SQLAlchemy session, so there are no HTTP round-trips and everything stays in one transaction.
  • RAG over university extension growing guides via a pgvector index in Postgres, with API-side embeddings so no model is loaded into the request process. This replaced a ChromaDB store whose onnxruntime and 79 MB embedding model could not fit a 512 MB instance.
  • Predictive watering engine built on FAO-56: soil moisture deficit from actual evapotranspiration minus effective rainfall, with ET₀ estimated by Hargreaves–Samani from stored min/max temperatures, crop coefficients from a 33-plant table, and a 0–100 urgency score adjusted for heat, wind, and forecast rain.
  • Weather tracking pulls 14 days of rainfall and temperature per garden from the Open-Meteo archive on an APScheduler job, so the deficit calculation always has fresh history.
  • Plant recommender scores a ~9,000-entry library against zone, season, sunlight, soil pH, difficulty, and companions — a rule-based weighted sum, plus a gradient-boosting classifier trained on 539K synthetic rows and evaluated with precision@k, recall@k, and NDCG@k.
  • Backend on Neon Postgres, migrated from SQLite in FK order with sequence resets. Connection pooling is sized to survive Neon’s free-tier autosuspend — pool_pre_ping transparently reconnects dropped sockets rather than erroring on the first query after idle.
  • Sentry for errors, slow-request warnings, and nightly job check-ins, with a path-based trace sampler, a before_send filter that drops expected probe errors, releases tagged to the deployed commit, and PII off by choice.
  • CI/CD on GitHub Actions: backend pytest, a Vite build and test, Android JVM unit tests, and a migrations job that builds the schema from Alembic revisions alone against a pgvector Postgres, then asserts it matches the models and reverses cleanly — a guard written after a column reached production without a migration. Render auto-deploys main; a scheduled workflow fires the nightly jobs and wakes both free-tier services.
  • Images live in a private Google Cloud Storage bucket, proxied by the backend under an immutable cache header so each device downloads a given photo once.

Stack FastAPI · SQLAlchemy · Alembic · React · TypeScript · Vite · Neon Postgres · pgvector · Kotlin · Render · Google Cloud Storage · Sentry · GitHub Actions

StudyDeck

Android

Spaced-repetition flashcards with cloud sync

A native Android flashcard app built to study for certifications — currently the AWS Developer Associate (DVA-C02) exam. Cards are rated during review and the schedule adapts to how well each one is actually known.

  • SM-2 scheduling from a 1–5 recall rating: a score below 3 resets the streak and returns the card tomorrow, successes step out to 1 day, 6 days, then the previous interval scaled by the card’s easiness factor, which is itself adjusted every review and clamped at 1.3.
  • Firebase sync — Firestore keeps subjects, decks, and cards under a per-user document tree, written in batches and pulled back on demand, with Firebase Auth supplying the identity. Room is the local source of truth, so the app works offline.
  • JSON import and export for bulk deck authoring: write a versioned deck file on a computer, transfer it, and import it as a new subject — which makes generating a 30-card service deck with an LLM a practical workflow. Export produces the same format, so decks round-trip between devices.
  • Markdown (CommonMark) in questions and answers, rendered in both the editor preview and the study flip card, for code, tables, and service limits.
  • Scheduled study reminders through a notification receiver, plus per-session summaries.

Stack Kotlin · Jetpack Compose · Room · Hilt · Navigation Compose · Coroutines · Firebase Auth · Cloud Firestore · Coil
